# Project Structure

```
my-app/
├── bootstrap/
│   └── app.ts                  # defineApp({ name })
├── src/
│   ├── config/                 # app, database, cache, kv, storage, mcp, ...
│   ├── app/                    # discoverable app constructs
│   │   ├── models/             # src/app/models/*.ts
│   │   ├── controllers/...     # src/app/http/controllers/*.ts
│   │   ├── middleware/...      # src/app/http/middleware/*.ts
│   │   ├── policies/           # src/app/policies/*.ts (Policy + Gate)
│   │   ├── services/           # src/app/services/*.ts
│   │   ├── jobs/               # src/app/jobs/*.ts
│   │   ├── tasks/              # src/app/tasks/*.ts
│   │   ├── events/             # src/app/events/*.ts (Event + Listener + Subscriber)
│   │   └── commands/           # src/app/commands/*.ts (defineCommand)
│   ├── ui/
│   │   ├── pages/              # definePage files (*.tsx)
│   │   └── layouts/            # layouts/*.tsx
│   └── database/
│       ├── migrations/         # timestamped SQL-step migrations
│       └── seeders/            # idempotent seeders
└── .kwiva/                     # generated: route-tree.gen.ts, serve.gen.ts, entry.client.tsx
```

## Key rules

- `src/app/**` and `src/ui/**` are convention folders — everything inside is discovered by name.
- Files exporting `defineX` factories are auto-discovered by convention (see [Auto-Discovery](/docs/core-concepts/auto-discovery)).
- One construct per file, in its own directory: models → `src/app/models/`, pages → `src/ui/pages/`, etc.
- Config files: `src/config/*.ts` — one file per section (section key = filename).
- `src/.kwiva/types/route-tree.gen.ts` is the **typed route map** consumed by `@kwiva/client`, `@kwiva/ui`, and editors (regenerated by `kwiva build` and `kwiva dev`).
